* Tests and performance benchmark

The behavioral tests exercise the observable contract of the filtered
regexp search, including direction, failure behavior, match data,
escaped commands, ignored regions, and point safety.

** Run the tests

: make test

The symbol tests generate the fixture automatically and compare overlays
against the original per-rule scanner. They cover custom-rule precedence,
duplicates, capture expressions, and cache reuse and invalidation after
in-place rule edits.

** Generate the performance fixture

The benchmark input is deterministic and contains no personal or
proprietary material. It is generated rather than committed to keep
the patch small:

: make fixture

Pass another size in KiB when a larger stress document is useful:

: emacs -Q --batch -l test/generate-large-fixture.el -- /tmp/large.tex 512

** Compare revisions

The comparison script builds isolated, byte-compiled copies of both
revisions and measures five 80-line viewports per iteration. From this
branch, compare merged PR #47 (=31eb152=) with the proposed change:

: make fixture
: MLB_BENCH_ITERATIONS=30 test/compare-performance.sh 31eb152 HEAD

The two arguments may be any locally available Git revisions. For
example, use =origin/master= instead of =master= after fetching the
upstream branch into a remote-tracking ref.

Set =MLB_BENCH_COMPILED=0= to compare source-loaded code. The =jit=
scenario invalidates the sampled viewport before timing
=jit-lock-fontify-now=. The remaining scenarios directly time the
complete Magic LaTeX pass or an individual display-feature family.
Overlay counts are printed as a basic output-parity guard alongside
the timings.

** Symbol-batching measurements

Measured on 2026-09-08 with byte-compiled GNU Emacs 30.2 on Apple Silicon,
using 30 iterations (150 samples per scenario) and the generated 128 KiB
fixture.  The candidate includes the content-aware cache fix.  The baseline
is merged PR #47 (=31eb152=), not the older recursive-search implementation.
Times are milliseconds.

| Scenario   | Baseline median | Candidate median | Baseline p95 | Candidate p95 | Mean overlays |
|------------+-----------------+------------------+--------------+---------------+---------------|
| jit        |          12.333 |            8.959 |       15.445 |        12.303 |         516.0 |
| full       |          13.588 |           10.046 |       17.051 |        13.336 |         495.6 |
| symbols    |           5.564 |            1.927 |        6.035 |         2.145 |         180.8 |
| no-symbols |           8.047 |            8.194 |       11.106 |        11.335 |         314.8 |
| blocks     |           5.163 |            5.255 |        7.725 |         7.844 |         193.2 |
| align      |           2.770 |            2.821 |        3.393 |         3.709 |           0.0 |

JIT and full-pass medians improve by approximately 27% and 26%, respectively;
the symbol median improves by 65%. The corresponding p95 reductions are
20%, 22%, and 64%.  Mean overlay counts match in every
scenario, and the tests compare canonical overlay contents as well as counts.
These are synthetic-fixture measurements, not a guarantee for every document.

Single-pass block scanning and broader built-in symbol batching are separate
follow-ups and are not included in this comparison.
* Follow-up measurements

The corrected, byte-compiled harness was run with 30 iterations (150 samples)
per revision.  Each implementation commit was compared directly with its
parent so that the improvements can be reviewed independently.

| Change                         | Scenario | Parent median | Commit median | Reduction |
|--------------------------------+----------+---------------+---------------+-----------|
| Single-pass block declarations | jit      |         9.298 |         8.125 |       13% |
| Single-pass block declarations | full     |        10.302 |         9.101 |       12% |
| Single-pass block declarations | blocks   |         5.385 |         4.175 |       22% |
| Broader built-in symbol batches | jit      |         8.206 |         7.291 |       11% |
| Broader built-in symbol batches | full     |         9.305 |         8.328 |       10% |
| Broader built-in symbol batches | symbols  |         2.011 |         1.006 |       50% |

Together, the follow-ups reduce =jit= and =full= medians by 21% relative to the
initial performance branch.  Against upstream =master=, the final compiled
=jit= median falls from 27.811 ms to 7.197 ms, =full= from 29.549 ms to
8.439 ms, and =symbols= from 19.546 ms to 0.971 ms.  Overlay counts are
unchanged.  A dense negated-symbol stress document also improves rather than
regresses: its symbol median falls from 4.889 ms to 2.287 ms.

The broader batching applies only when the built-in symbol table is unchanged.
Customized symbol tables retain the order-preserving plan, including overlaps
and duplicate rules.

#+title: Magic LaTeX tests and performance benchmark

This directory contains a deterministic generator for a synthetic 128 KiB
LaTeX fixture, behavioral ERT tests, overlay-parity checks, and a viewport
benchmark.  The generated fixture contains no personal material and is not
committed.

* Run the tests

#+begin_src shell
make test
#+end_src

The fixture is generated automatically when needed.  The 13 tests cover the
filtered-search contract, escaped commands, comments and verbatim regions,
overlay parity, custom-rule precedence (including duplicates and capture
expressions), cache reuse, and in-place edits to custom symbol rules.

The cache regression exercises regexp replacement, destructive regexp-string
editing, whole-rule replacement, display replacement, and list extension.

* Rebuild the fixture

#+begin_src shell
make fixture
#+end_src

The generator is deterministic.  To generate a larger stress document:

#+begin_src shell
emacs -Q --batch -l test/generate-large-fixture.el -- /tmp/large.tex 512
#+end_src

* Compare revisions

Compare the merged iterative-search baseline with this branch:

#+begin_src shell
git fetch upstream
make fixture
MLB_BENCH_ITERATIONS=30 test/compare-performance.sh 31eb152 HEAD
#+end_src

Use the remote name configured for =zk-phi/magic-latex-buffer= if it is not
=upstream=.  The script accepts any two local Git revisions and byte-compiles
both by default.  Set =MLB_BENCH_COMPILED=0= to compare source-loaded code.

Each iteration samples five 80-line viewports.  The =jit= scenario invalidates
each viewport before calling =jit-lock-fontify-now=.  The =full= scenario times
block highlighting, alignment, sub/superscripts, and symbols directly.  Other
scenarios isolate individual feature families.

* Phase-two measurements

Measured on 2026-09-08 with byte-compiled GNU Emacs 30.2 on Apple Silicon,
using 30 iterations (150 samples per scenario) and the generated 128 KiB
fixture.  The candidate includes the content-aware cache fix.  The baseline
is merged PR #47 (=31eb152=), not the older recursive-search implementation.
Times are milliseconds.

| Scenario   | Baseline median | Candidate median | Baseline p95 | Candidate p95 | Mean overlays |
|------------+-----------------+------------------+--------------+---------------+---------------|
| jit        |          12.333 |            8.959 |       15.445 |        12.303 |         516.0 |
| full       |          13.588 |           10.046 |       17.051 |        13.336 |         495.6 |
| symbols    |           5.564 |            1.927 |        6.035 |         2.145 |         180.8 |
| no-symbols |           8.047 |            8.194 |       11.106 |        11.335 |         314.8 |
| blocks     |           5.163 |            5.255 |        7.725 |         7.844 |         193.2 |
| align      |           2.770 |            2.821 |        3.393 |         3.709 |           0.0 |

JIT and full-pass medians improve by approximately 27% and 26%, respectively;
the symbol median improves by 65%.  Mean overlay counts match in every
scenario, and the tests compare canonical overlay contents as well as counts.
These are synthetic-fixture measurements, not a guarantee for every document.

Single-pass block scanning and broader built-in symbol batching are separate
follow-ups and are not included in this comparison.
